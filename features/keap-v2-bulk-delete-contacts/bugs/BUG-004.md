# BUG-004 — APPROVAL_SECRET accepted via query string on /admin/mint-client

> Reported: 2026-06-18 | Source: Codex adversarial review (CF-1) | Severity: high
> Status: reported | Bucket: **spec-gap** (security)

## Symptom
The credential that controls OAuth-client creation travels in the URL query string.

## Expected
Admin auth secret transported where it won't leak (header or POST body), not in URLs
(which land in logs, shell history, browser history, CF observability).

## Actual
`src/worker.ts` `/admin/mint-client` reads `secret` from `url.searchParams` (pre-existing in
base `feat/keap-v2-remote-worker`). My verification scripts (`scripts/deployed-do-proof.mjs`,
`scripts/deployed-regression-check.mjs`) also pass it as `?secret=`. The endpoint returns a
fresh client id/secret → a leaked secret enables unauthorized remote MCP access until rotated +
minted clients revoked.

## Reproduction
`POST /admin/mint-client?secret=<APPROVAL_SECRET>&redirect=...` → 200 with client creds.
Secret now in any URL-capturing surface.

## Root-cause hypothesis
Admin endpoint authored to read the query string; secure-transport requirement never specified.
This feature did not introduce the endpoint but its scripts propagate the insecure pattern, and
the deploy + live proofs exercised it.

## Evidence
- src/worker.ts:98-103 (`params.get('secret')`).
- scripts/deployed-do-proof.mjs / deployed-regression-check.mjs build `?secret=`.
- This session pasted APPROVAL_SECRET in plaintext (already at-risk → rotate).

## Affects / violated contract
No FR specified secure admin auth → spec-gap. Touches pre-existing `worker.ts` (out of this
feature's original scope) + my scripts.

## Recommendation (needs change-request; do NOT silently patch the shared worker)
Header/body-based admin auth on `/admin/mint-client`; rotate APPROVAL_SECRET; revoke clients
minted under the exposed secret (incl. test client wj5RzQDmYJzCw9Xh).

## Non Production Elements
None. Defect report; no code changed.
